# Generate Session Digests on Demand Outside Session Logs

A Session Digest is generated only after an explicit action in the Session Inspector. The Host inspects the addressed Session, runs a separate auxiliary model request, and caches the result by source revision. Concurrent requests for the same revision share one model operation, but each caller owns only its own wait: cancelling one caller does not cancel work still needed by another, and the final departing caller releases the shared operation. A later request starts fresh work rather than joining an already cancelled operation. During plugin disposal the module stops accepting requests, aborts its owned inspection/model work, and waits for every admitted call and orphaned provider operation to settle before its Host service disappears. The digest remains a read-only projection: it is never appended to the Session log, never changes Session Lineage, and becomes stale when newer activity appears. This keeps model cost and disclosure intentional while allowing any Selected Session—not only the Viewed Session—to be summarized.
